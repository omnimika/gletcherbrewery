## Текущие замечания

### F01 — P1: lint снова не проходит, теперь в галерее

[product-gallery.tsx](../../src/components/catalog/product-gallery.tsx):31,44–47.
Свежий ESLint: `react-hooks/set-state-in-effect` на `setMounted(true)`.
Прежняя ошибка меню исправлена, аналогичный паттерн добавлен в карусель.
Пересмотреть определение overflow/колонок через CSS либо корректную подписку
на внешний размер с SSR snapshot. Не отключать правило и не маскировать
его таймером ради lint. Проверить hydration и появление стрелок.

### F02 — P2: origin focus сохраняется после initial focus

[main-nav-overlay.tsx](../../src/components/main-nav-overlay.tsx):30,32–47;
[use-focus-trap.ts](../../src/lib/use-focus-trap.ts):23–39.
Effect trap сначала фокусирует первую ссылку диалога. Следующий effect сохраняет
`document.activeElement`: уже внутреннюю ссылку, а не кнопку открытия.
После закрытия пытается сфокусировать удалённый элемент. Аналогичный порядок
у [age-gate.tsx](../../src/components/age-gate.tsx):16,25–40.
Снятие inert исправлено, но R02 закрыт лишь частично. Сохранить origin до
initial focus; объединить lifecycle либо передать trigger. Проверка: Enter
на меню → Tab/Shift+Tab → Escape/крестик → activeElement равен кнопке меню.
Для age gate определить точку продолжения. Вывод статический; browser не запускался.

### F03 — P2: ссылка второго языка имеет низкий контраст

[locale-switch.tsx](../../src/components/locale-switch.tsx):47–49 даёт доступной
ссылке `opacity-20`. Navy `#0d0f49` на ice `#e6eefc` даёт расчётно **1,53:1**
при тексте 14–17px. Это действующая ссылка, не disabled-control. Сделать
resting/focus/hover читаемыми, active выделить дополнительно оформлением.
Проверить computed colors. [WCAG 1.4.3](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)
требует для такого обычного текста минимум 4,5:1.

### F04 — P2: карусель теряет минимальную высоту artboard

[product-gallery.module.css](../../src/components/catalog/product-gallery.module.css):6–12,106–116.
Viewport heights добавлены, но пиксельные минимумы заменены `16rem`.
Сохранённый [HTML](../discovery/_raw/page__beer.html), `rec802918687`,
при 1200–1399px задаёт `min-height:700px; height:80vh`.
На **1200×600** Next даёт **480px**, исходный CSS — минимум **700px** до upscale.
R07 полностью не закрыт. Сверить runtime через MCP + браузер, зафиксировать
breakpoint/min-height/upscale контракт. Два Tilda-документа также расходятся
по desktop-колонкам около 1200px — не выбирать описание наугад.

Дополнительно сверить шаг стрелки: сейчас ширина slot (TSX:58–62), NLM127
описывает 320px с масштабированием; стрелки в CSS внутри stage, editor-аудит
помещает их в hero. Desktop mouse drag отсутствует при документированном
`moveOnPress`; native touch/trackpad scroll уже есть. Это задачи source parity,
а не требование переносить NOLIM runtime. Допустимые изменения UX согласовать.

### F05 — P2: ALL зависит от порядка detail-фикстуры

[catalog.ts](../../src/content/catalog.ts):106;
[catalog-filter.ts](../../src/content/catalog-filter.ts):24–43;
[products.ts](../../src/content/products.ts):58–62,205–212.
CATALOG строится по PRODUCT_PROPS; NEW/rest сохраняют этот входной порядок.
ALL фактически начинается **MoA NA, Tour, Cynic, Ausweis, Heidegger, Rouge…**,

Порядок detail-данных не должен определять порядок витрины. Получить актуальный
RU/EN ALL/category order из MCP, сопоставить по stable ID, хранить display order
явно. Старый HTML и комментарий не подтверждают сегодняшний порядок редактора.

### F06 — P2: навигация ведёт в отсутствующие локальные разделы

## Статус прежних замечаний и gate-проверки

- R03 UI messages и R05 home metadata закрыты по коду; browser проверка нужна.
- R06 scroll reset, R08 client import graph, R09 preload исправлены по коду;
  подтвердить новым build/bundle/UX. LCP не измерялся.
- R04: `permanentRedirect` обычно даёт **308**, не 301; streaming может дать
  meta redirect. [Документация Next.js](https://nextjs.org/docs/app/api-reference/functions/permanentRedirect).
  Комментарий «accepted» не является решением: AGENTS требует 301 для изменённых
  legacy URL. Для них сохранить 301; отдельно описать политику aliases и проверить
  HTTP без автоматического follow. Постоянство реализовано, согласованность открыта.
- Global 404/unknown URL/planned locale требуют runtime: root passthrough,
  html/body ниже `[locale]`. Это gate, не свежая воспроизведённая runtime-ошибка.
- `discontinued`/«Нет в наличии» — редакционная маркировка, не источник остатков.
  Проверить семантику по источнику/владельцу.

## Многоязычная архитектура

Основа соответствует ADR: один ID, localized slug/copy, отдельные UI messages,
published/draft, registry, язык отдельно от рынка. RU/EN сейчас полные.
Добавить язык только в registry пока недостаточно:

1. `catalog.ts`:109,235 и metadata home/listing явно перечисляют RU/EN.
   Вывести peers/сборку переводов из registry + публикации, без draft URL.
2. `LocaleSwitch` объявляет `Partial<Record<PublishedLocale,string>>`, но
   проверяет null. Undefined peer превращается в текущий pathname. Нужен явный
   missing-peer контракт и для header, и для detail. Текущие 36 полных переводов
   этот крайний случай не демонстрируют.
3. `pickCopy` имеет fallback; UI `request.ts` загружает только активный JSON.
   До новой локали определить required-key/fallback политику UI. Юридические
   строки должны иметь утверждённый перевод, а не скрытый fallback.
4. Для `sr` определить Latn/Cyrl; проверить glyph coverage, font fallback и
   лицензии для `hy`/`ka`/`sr`, uppercase/line-height, длинный немецкий текст,
   числа и компактный picker. Язык не включает автоматически новый рынок.
5. Проверки: draft/missing, slug collisions, разные slug, недоступные peers,
   canonical/hreflang только опубликованных версий, html lang, 404.

Это задачи перед публикацией новых локалей, а не требование сейчас переводить
весь сайт или задерживать RU/EN приёмку неутверждёнными языками.
