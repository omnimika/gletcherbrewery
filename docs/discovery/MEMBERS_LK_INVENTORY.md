# Members / Личный кабинет — инвентаризация

> Дата: **31 октября 2026**  
> Доступ: владелец предоставил тестовый вход для read-only осмотра.  
> Формы **не отправлялись**, покупки/списания **не выполнялись**, чеки **не загружались**.  
> Пароль и секреты **не сохраняются** в репозитории.  
> Статусы: **Confirmed** / **Observed** / **Assumed** / **Unknown**

## 1. Ключевое уточнение по auth vs Collabza

| Слой | Факт |
|---|---|
| Login / session на `gletcherbrewery.com/members/*` | **Tilda Members** (`members.tildaapi.com`) |
| Collabza | **Не auth сайта.** Это хаб трансфера Zero Block ↔ Airtable/Bipium (см. `INTEGRATIONS_AUDIT.md`) |
| Airtable + Make | Source of truth / автоматизации бонусов, чеков, заказов |

**Confirmed:** `/members/login` — UI Tilda Members; после входа `/members/lk`. Данные профиля/баланса подтягиваются через Collabza scripts из Airtable (и частично Bipium).

**Следствие для миграции (этап 7):** заменить связку **Tilda Members + Collabza + Airtable + Make** на **своя auth + PostgreSQL ledger + серверные API** (NocoDB как admin UI). Пароли Tilda Members 1:1 не экспортируются.

### 5.2. Модель лояльности — Observed UI copy (не утверждённые бизнес-правила)

Тексты на экране (нужна сверка с Airtable/формулами):

- Валюта: **биркоин ₿**, заявленный курс UI: **1 ₿ = 1 ₽**.
- Баланс: «всего накоплено» / «всего списано».
- Уровни: +1 уровень за каждые **1000** заработанных биркоинов; каждый 5-й (юбилейный) повышает статус и даёт приз; главный приз — годовое снабжение пивом.
- Статус-пример в UI: «Первооткрыватель»; приз уровня — «ящик регулярного сорта»; прогресс «до следующего уровня: N ₿».
- Рефералка: уникальная ссылка вида  
  `/members/lk?utm_source=…&utm_medium=referral&utm_campaign=friends`  
  Приглашённые при покупках Gletcher начисляют **1%** пригласившему (**текст UI**).
- Офлайн-чеки: **3%** от стоимости продукции Gletcher; только чеки с QR.

**Важно:** цифры баланса конкретного аккаунта — персональные данные; в документации фиксируем только **наличие полей**, не целевые значения.

## 9. Риски миграции

1. Tilda Members credentials/session **не переносятся** автоматически.  
2. Правила %/уровней нужно подтвердить по Airtable/формулам, не по UI-тексту.  
3. Upload чеков + OCR/ручная модерация — отдельный workflow.  
4. Реферальные UTM/параметры завязаны на Tilda record ids.  
5. «Error get alias» — проверить до копирования поведения.  
6. Магазин наград смешивает ₽ и ₿ — платёжная/списательная модель Open.
